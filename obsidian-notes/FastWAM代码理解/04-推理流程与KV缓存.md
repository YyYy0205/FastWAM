# 推理流程与 KV 缓存

**源文件**：`src/fastwam/models/wan22/fastwam.py`，`infer_action()` 第 905 行
**相关笔记**：[[00-索引]] | [[02-MoT混合Transformer]] | [[03-训练Loss全流程]]

---

## 1. 两种推理模式对比

| 模式 | 函数 | 视频专家运行次数 | 动作专家运行次数 | 用途 |
|------|------|----------------|----------------|------|
| `infer_action` | 第 905 行 | **1 次**（预填充 KV 缓存） | N 次（每步去噪） | 机器人控制，生产使用 |
| `infer_joint` | 第 726 行 | N 次（每步都跑） | N 次 | 可视化/调试，同时生成视频+动作 |

N = `num_inference_steps`，默认 20。

> [!success] FastWAM 的核心优势
> `infer_action` 中视频专家只运行一次：
> - **节省**：(N-1) × 30 次视频 Transformer 前向计算
> - **代价**：30 层的 K/V 缓存（显存）
> - 这就是论文题目 "Do World Action Models Need Test-time Future Imagination?" 的答案：**不需要**。

### 阶段 2：视频 KV 缓存预填充（只执行一次）

# 视频专家用 timestep=0（干净图像，无噪声）处理第一帧
timestep_video = torch.zeros([1])   # t=0

video_pre = video_expert.pre_dit(

#### prefill_video_cache 内部逻辑（`mot.py` 第 257 行）

```python
def prefill_video_cache(self, video_tokens, ...):
    expert = self.mixtures["video"]
    x = video_tokens   # [1, 196, 3072]
    kv_cache = []

    for layer_idx in range(30):
        block = expert.blocks[layer_idx]

        # 计算本层 Q/K/V
        q, k, v, residual_x, ... = _build_expert_attention_io(expert, block, x, ...)

        # 视频自注意力（只有视频 token，用视频自身的 mask）
        mixed = _mixed_attention(q, k, v, video_attention_mask)  # [196, 196]

        # 更新视频 token（用于下一层输入）
        x = _apply_expert_post_block(block, residual_x, mixed, ...)

        # 保存本层 K/V 到缓存
        kv_cache.append({"k": k, "v": v})
        #                 ↑ k: [1, 196, 3072]  这是本层视频 token 的 Key
        #                        ↑ v: [1, 196, 3072]  Value

    return kv_cache
```

> [!tip] 为什么 K/V 可以缓存？
> 视频分支的输入在整个推理过程中**固定不变**（第一帧 + timestep=0 + context 不变），
> 所以每层的 K/V 不会随去噪步变化，可以一次计算、20 次复用。

### 阶段 3：扩散去噪循环（20 步）

```python
# 调度器生成时间步序列：t 从 1.0 → 0.0
infer_timesteps, infer_deltas = scheduler.build_inference_schedule(
    num_inference_steps=20,
    shift_override=sigma_shift,
)
# infer_timesteps: [t_19, t_18, ..., t_0]  从大到小（1.0 → 0.0）
# infer_deltas:    [Δt_19, Δt_18, ..., Δt_0]  每步步长

for step_t, step_delta in zip(infer_timesteps, infer_deltas):
    timestep_action = step_t.unsqueeze(0)  # [1]

    # 动作专家 pre_dit（每步都要重新计算，因为 t 和 latents_action 在变）
    action_pre = action_expert.pre_dit(
        action_tokens=latents_action,      # [1, 16, action_dim]  当前噪声动作
        timestep=timestep_action,          # [1]
        context=context,
    )

    # 用缓存 K/V 运行动作分支（30 层）
    action_tokens_out = mot.forward_action_with_video_cache(
        action_tokens=action_pre["tokens"],         # [1, 16, 1024]
        action_freqs=action_pre["freqs"],
        action_t_mod=action_pre["t_mod"],
        action_context_payload={...},
        video_kv_cache=video_kv_cache,              # 复用缓存，不重新计算
        attention_mask=attention_mask,              # [212, 212]
        video_seq_len=196,
    )
    # action_tokens_out: [1, 16, 1024]

    # 预测去噪方向
    pred_action = action_expert.post_dit(action_tokens_out, action_pre)
    # [1, 16, action_dim]

    # 流匹配更新：x_{t-Δt} = x_t - Δt × pred
    latents_action = scheduler.step(pred_action, step_delta, latents_action)
    # 每步把动作 latent 向预测的方向推进一小步
```

#### `forward_action_with_video_cache` 内部（`mot.py` 第 343 行）

```python
for layer_idx in range(30):
    block = expert.blocks[layer_idx]

    # 动作 Q/K/V 每步都重新计算（因为输入在变）
    q_action, k_action, v_action, ... = _build_expert_attention_io(
        expert, block, x, action_freqs, action_t_mod
    )

    # 取出本层的视频缓存 K/V
    k_video = video_kv_cache[layer_idx]["k"]  # [1, 196, 3072]
    v_video = video_kv_cache[layer_idx]["v"]  # [1, 196, 3072]

    # 拼接 K 和 V（视频在前，动作在后）
    k_cat = torch.cat([k_video, k_action], dim=1)  # [1, 196+16, 3072]
    v_cat = torch.cat([v_video, v_action], dim=1)  # [1, 196+16, 3072]

    # 只用动作 Q 做注意力
    # action_attention_mask 是 attention_mask 中动作行的切片
    # → [16, 212]（动作 token 对全序列的可见性）
    mixed = _mixed_attention(
        q_cat=q_action,   # [1, 16, 3072]
        k_cat=k_cat,      # [1, 212, 3072]
        v_cat=v_cat,      # [1, 212, 3072]
        attention_mask=action_attention_mask,  # [16, 212]
    )
    # mixed: [1, 16, 3072]

    x = _apply_expert_post_block(block, residual_x, mixed, ...)
```

## 3. 推理计算量对比

以 `num_inference_steps=20`，`S_v=196`，`T=16` 为例：

| 操作 | `infer_action` | `infer_joint` |
|------|--------------|--------------|
| 视频 pre_dit | 1 次 | 20 次 |
| 视频 30 层 Transformer | 30 次（预填充） | 20 × 30 = 600 次 |
| 动作 pre_dit | 20 次 | 20 次 |
| 动作 30 层 Transformer | 20 × 30 = 600 次 | 20 × 30 = 600 次 |
| 视频 post_dit | 0 次 | 20 次 |
| **视频专家总计** | **30 次** | **640 次** |

## 4. 扩散去噪可视化

```
t=1.0  latents_action = [纯噪声]
  ↓ 去噪步 1（pred = 预测流场方向）
t=0.95 latents_action = [稍微去噪]
  ↓ 去噪步 2
t=0.90 latents_action = [更多去噪]
  ...（共 20 步）...
t=0.0  latents_action = [干净动作]
         ↓ 反归一化
       [最终输出动作序列]
```

每步更新公式（流匹配 Euler 积分）：
```
x_{t-Δt} = x_t - Δt × model(x_t, t)
```

## 5. 关键参数速查

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `num_inference_steps` | 20 | 扩散去噪步数，越多越慢越精确 |
| `action_horizon` | 16 | 预测未来多少步动作 |
| `sigma_shift` | None（用 config 中的 5.0） | 调度器时间步偏移 |
| `seed` | 需指定 | 控制随机性，评测时固定 |
| `tiled` | False | VAE 分块编码（显存不足时用） |
